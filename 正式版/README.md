# 复扫雷 · 正式版（原生单 exe）

> **想看"这游戏是怎么从零做出来的"**：项目根的 [`从零做出复扫雷.md`](../从零做出复扫雷.md)
> 是从零基础开始的全过程教材（从"什么是程序"讲到交付一个 exe）；
> 这份 README 只讲实现细节、设计取舍和踩过的坑。

> **命名规则（别再改回去）**：产物名是 **`复扫雷 <版本>.exe`**（交付/存档），另有同一份构建的
> 稳定副本 **`复扫雷.exe`** 供脚本与自检使用；窗口标题是 `复扫雷 Complexweeper`，
> 关于对话框标题是 `关于复扫雷`，自检报告抬头也是 `复扫雷 · …`。
> 「复数扫雷」只留在历史文档（`RULES.md` 等）、网页原型 `demo/`、以及项目根那个早先网页版产物
> `release\复数扫雷.exe` 里。

> **版本号纪律**：当前 **1.0.11**。版本号只写在 `src/main.zig` 的 `APP_VERSION` 一处，
> 「关于」对话框的第一行、规则自检与界面自检的报告抬头、**构建产物的文件名**都读它——
> 所以以后改东西时**顺手把这个常量 +1** 就行，别的地方不用动（第三位小改、第二位加功能、第一位大改）。
> 自检里有两条断言盯着：版本号必须是 `数字.数字.数字` 的形状，且「关于」正文里必须带着它。

**`复扫雷 1.0.10.exe` —— 398 KB，双击就跑，不装任何东西。**

原生 Win32 程序（GDI 绘制，手写 Win32 绑定），不含浏览器内核、不含 .NET/Java/Electron 之类运行时，
编译产物只导入系统自带的 `KERNEL32 / USER32 / GDI32 / ntdll`。所有贴图（61 张，含 32×32 程序图标）以图集形式编进 exe，
运行时不读任何外部文件。

```
正式版/
  复扫雷.exe        ← 唯一产物（双击即玩）
  build.ps1           ← 一键构建：生成图集 → 编译 → 注入图标 → 自检
  src/
    main.zig          窗口、菜单、对话框、绘制、输入、截图/自检入口
    game.zig          规则与状态（不碰 Win32，可单独测）
    win32.zig         手写 Win32 绑定（只声明用到的部分，无第三方包、无 libc）
    selftest.zig      规则自检（31 条断言）
    uitest.zig        界面自检（197 条断言，直接投递菜单/鼠标/键盘消息）
    assets.zig        由 tools/gen_atlas.js 生成（图集索引）
    atlas.bin         由 tools/gen_atlas.js 生成（61 张贴图打包，88 KB）
  tools/
    gen_atlas.js      读 素材/图集.png + 图集.json 打包成图集，并生成 assets.zig（唯一的素材来源）
    set_icon.js       把 素材/图标.png 写成 .rsrc 图标（16/32/48 三档），手工构造 PE 资源树
    inspect_exe.js    检查 PE：子系统、导入表、是否含 CLR
    dump_atlas.js     把编进 exe 的那张图集导成 PNG + 槽位表 json + 逐张散图（都是 1:1）
    png.js            最小 PNG 编解码 + 逐像素比较，下面几个脚本共用
    diff_sprites.js   比较两个散图目录，列出这一轮改了哪几张、各改了几个像素
    check_export.js   导出验收：矩形表对 json、像素对 素材/图集.png、散图对图集
    cmp_tiles.js      把指定槽位「左旧右新」并排画成一张图，看改动一目了然
    bmp2png.js        --shot 输出的 BMP 转 PNG，方便核对渲染
    update_assets.ps1 一条命令跑完素材更新（存档 → 升版本 → 重建 → 导出 → 比对 → 对照表 → 抖动）
```

> `crop.js` 截图裁剪）只留在本机，不随仓库发布；正文里提到它们的地方照旧，做法可复现。

## 构建

需要两样东西，都是解压即用、无需安装：

| 依赖 | 用途 | 获取 |
| --- | --- | --- |
| Zig 0.14.1（windows-x86_64） | 编译器（自带 MinGW 头文件与链接器，不依赖 MSVC） | 解压到 `%LOCALAPPDATA%\zig-0.14.1\` |
| Node.js | 只在构建期用于打包图集、注入图标，**运行期不需要** | 任意版本 |

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

脚本会依次：生成图集 → `zig build-exe -O ReleaseSmall --subsystem windows` → 注入图标 →
跑规则自检与界面自检 → 打印最终 exe 大小与导入表。加 `-NoTest` 可跳过自检。

**产物是两个文件（同一份构建，逐字节相同）**：

| 文件 | 用途 |
| --- | --- |
| `复扫雷 <版本>.exe` | 交付/存档用，名字里带版本号（版本号从 `src\main.zig` 的 `APP_VERSION` 读，构建时自动命名） |
| `复扫雷.exe` | 稳定名的副本：自检、`tools\` 里的脚本、快捷方式都读它，改版本号时不用跟着改脚本 |

构建结束会比对两者的 SHA-256，不一致直接报错；所以不存在"稳定副本偷偷落后一版"这种事。
旧版本的 `复扫雷 <版本>.exe` 会留在目录里当历史，想清理随手删掉即可（进程占用检查按
"进程名里带扫雷"匹配，删哪个都不影响构建）。

每一步的退出码都会检查，任何一步失败就中止。注入图标前会独占试开一次 `复扫雷.exe`：
**如果还有个实例在跑，文件被占用，脚本会直接指出 pid 让你先关掉**——
之前这里只靠 Node 抛 EBUSY，而脚本照样往下走、拿旧 exe 跑自检、最后还打印"完成"，
看起来一切正常，实际上产物根本没更新。现在这种沉默失败被堵掉了。

## 规则（与 `RULES.md` 一致）

- 四种雷 `+1 / −1 / +i / −i`，每颗模长都是 1。
- 非雷格显示周围复数和的模长平方 $D=|S|^2=a^2+b^2$，以整数或最简根式显示；**只有 24 个值可能出现**
  （$0,1,2,4,5,8,9,10,13,16,17,18,20,25,26,29,32,34,36,37,40,49,50,64$）。
- **邻域一颗雷都没有才显示空白；有雷但正好相消则显示 `0`**，两者含义完全不同。
- **空白格点击会连片翻开**（连同边界上的数字格）；显示 `0` 的格子与数字格只翻开自己。
- **旗帜不限量**，右键循环 `空 → +1 → −1 → +i → −i → 空`（清旗就是把旗循环回「空」）。
  开局公开每种雷各有多少颗——这是展开判据的必需输入，不是限制。
- **展开判据（严档，中键或左右键同时点击触发）**：邻域旗帜总数 = 邻域真实雷总数，
  且实旗/虚旗数量与真实实/虚雷数一致（实虚顺序不限）。
  判据不通过时**棋盘上不给任何提示**，只是什么都不发生；旗帜位置插错仍可能踩雷。
- **胜利 = 翻开所有非雷格**，旗帜完全不参与判定。

## 操作

| 操作 | 效果 |
| --- | --- |
| 左键按下 | **只把那一格压住**（画成已翻开的空白格），不翻开、不开局 |
| 左键松开 | 在按住的那一格上松手才真翻开；第一下点击决定开局，该格及其 8 邻居保证无雷。**插了旗的格子翻不开**（旗子保护它） |
| 左键拖动 | 按住不放拖到别的格子，「压住」跟着走；拖出棋盘就取消（松手什么都不翻） |
| 右键 | 循环插旗（**开局前也能插**，旗帜会留到开局之后） |
| 中键按住 | 只预览：周围**即将被展开**的格子先显示空白贴图（按住期间人脸播「脸扫雷」） |
| 中键松开 | 按判据展开该数字格周围未插旗的格子（判据不过则什么都不发生） |
| 左右键同时点击 | 同中键（按住预览、松手才展开）；**双击不再是展开触发器** |
| <kbd>F2</kbd> | 按当前难度重开 |

「按下预览、松开才翻开」是传统扫雷的做法：按下时那一格画的是 `已翻开空白按钮.png`，
松手时看的也是"松手落在哪一格"，所以拖着走一圈再松手，翻开的是最后停下的那一格。

**没有单独的「清除旗帜」操作**：中键已经改作展开，想撤旗就把右键循环转到「空」。
注意左键**点不开插了旗的格子**（传统扫雷的规矩：旗子保护那一格），所以撤旗只能走右键循环。

**局面结束后雷区彻底不再响应**：胜利或失败之后，点格子不会再有"按下"预览、右键也不会再插旗
（人脸按钮、F2、菜单照常可用——重开走它们）。这是传统扫雷的行为：结束就是结束了。

**人脸的四种状态，各管一段**：

| 脸 | 什么时候 |
| --- | --- |
| `脸普通` | 平时 |
| `脸扫雷` | **棋盘上按着键期间**（左键准备翻开 / 左右键同时准备展开 / 中键准备展开 / 右键插旗后一直按着），以及动作完成后约 200ms（一次性定时器收回） |
| `脸按下` | **只有按住人脸按钮本身**才播：游戏中途按 = 重开；**胜利/失败后按 = 准备新开局** |
| `脸死亡` / `脸胜利` | 局面结束；优先级最高，结束那一瞬间也不会闪 `脸扫雷` |

菜单：`游戏(G)` = 开局 / 初级 / 中级 / 高级 / 自定义… / **最高分纪录…** / 缩放 100–300% / 退出；
`帮助(H)` = 玩法与操作 / 关于。

「自定义…」是一个真正的 Win32 对话框（自己写的窗口类 `ComplexSweeperDlg`，不是资源里的模板）：
**整窗白底**，两行尺寸（高度 9–30、宽度 9–40），下面四行是**四种雷各自的颗数**——标签写作
`正实雷` / `负实雷` / `正虚雷` / `负虚雷`（与素材文件名、README 配色表一致，不再带 `+1/−1/+i/−i` 前缀），
合计 = 总雷数、上限 = 格数 − 9。某种填 0 就得到纯实数局或纯虚数局——那时所有显示值都会是完全平方数。

> 白底这件事有两个坑，都踩过：**静态标签必须由父窗口回一块白刷子**（`WM_CTLCOLORSTATIC`），
> 否则默认刷子会在"按合计均分"右边画出一条白条——那其实是**校验提示那格空白 STATIC**，
> 白底白刷子之后它就隐形了，只有出错时才显出文字（`高度要在 9 – 30 之间。` 之类）。
> 另外对话框里**不用**再画"四种雷各自的颗数（合计 = 总雷数）"那行提示：四个标签本身就说明了，
> 去掉之后窗口高度也收窄了 22 像素。

## 最高分纪录

**三档标准难度各记一个最快通关用时（秒）**，破了纪录会立刻弹窗报喜：

- 纪录写在 `HKEY_CURRENT_USER\Software\Complexweeper`（值名 `Beginner` / `Intermediate` / `Expert`，DWORD 秒数）——
  和原版扫雷一样用注册表，所以分发仍然只有一个 exe，不会在旁边多出存档文件。
- 一律按**整数秒**记；慢于现有纪录不会覆盖（自检里有"更快覆盖 / 更慢不动"两条断言）。
- **自定义棋盘不计入**：尺寸与雷数随意，比时间没有意义（原版也是这个规则）。判定方式是拿棋盘尺寸
  与三档预设逐一比对，对上才算标准档。
- 「游戏 → 最高分纪录…」随时看三档成绩；这个弹窗**只有三行纪录**（`初级      12 秒`），
  不写棋盘尺寸、不写说明文字、也不显示存档位置（难度名统一两字，三行的用时正好对齐一列）。
  刚破纪录时弹窗标题会变成「新纪录！」。自检里有一条断言直接把弹窗正文取出来核对：
  `testScoresText()` 走的就是画弹窗那段代码，行数、三档数值、占位符、以及"不该出现的东西"逐项检查。

## 玩法与操作 / 关于

两个都是 `MessageBoxW` 弹的原生对话框，文案是编译期字面量（能用 `strings` 直接从 exe 里核出来）：

- **玩法与操作**分三小段：开头一行点明四种雷的名字（正实雷 / 负实雷 / 正虚雷 / 负虚雷），
  然后五行操作（左键 / 右键 / 中键或左右键同时点击 / F2）、数字含义、展开条件。
  **雷说雷的名字、旗说旗的名字，一律不写 `+1/−1/+i/−i` 这类符号**：四种雷是「正实雷、负实雷、正虚雷、负虚雷」，
  插旗顺序是「正实旗、负实旗、正虚旗、负虚旗」。自检里有四条断言盯着这段文案：顺序那行必须是旗的名字、
  四种雷那行必须是雷的名字、不能再出现旧写法、正文里不能出现 `+1`/`-1`。
- **关于**按"克隆作品"的经典署名格式排（参考 Minesweeper X 的 About 页）：
  `复扫雷 Complexweeper <版本号>` → `基于 Microsoft® 扫雷(原版作者：Robert Donner、Curt Johnson)` → 空行 →
  `图像素材来源：…` → `Copyright © 2026 青月晓` → `本程序为免费软件` → `与 Microsoft 公司无隶属关系`。
  中间那两行是这一套的关键：**新作的版权**与**原作的署名**分开写，原作署名不等于授权；
  最后一句 disclaimer 管的是"来源混淆"（别让人以为这是微软出的），不是"使用许可"。
- 原来的「显示值对照表」菜单项已删除（那 24 个值在 `RULES.md` 里有完整推导，界面里不再重复）。
- 窗口标题、关于对话框的标题栏都跟着产品名走：`复扫雷 Complexweeper` / `关于复扫雷`。
  自检里有一条断言把 `GetWindowTextW` 读出来的标题与 `APP_TITLE` 常量比对，并检查标题里
  只剩「复扫雷」、不再出现「复数扫雷」，英文名 `Complexweeper` 保留。

自检里通过 `--demo-win --quiet` 走的是同一条结算路径（冻结用时 → 比纪录 → 落盘），
所以"能不能存进去、会不会误覆盖"都有实测，不是只测一个比较函数。

## 程序图标（三处共用同一张素材）

图标只有一份来源：`素材/图标.png`（32×32，**带 alpha 通道**——别的贴图都是不透明的，只有它有透明像素）。

| 用在哪 | 怎么来的 |
| --- | --- |
| 文件图标（资源管理器/任务栏） | `tools/set_icon.js` 把图集里的 `icon` 槽位写成 `.rsrc` 里的 RT_GROUP_ICON，含 **16 / 32 / 48** 三档 |
| 窗口图标（标题栏/Alt+Tab） | 运行时 `LoadIconW(hInst, MAKEINTRESOURCE(1))` 取那份资源；16×16 那一档用 `LoadImageW` 单独点名 |
| 「关于」弹窗左侧的图标 | `MessageBoxIndirectW` + `MSGBOXPARAMS.lpszIcon` 指同一个资源 |

三档尺寸不是简单缩放：**16×16 用 2×2 方框平均**（原图是点阵抖动，隔点抽样会把中间灰抽没），
32×32 是原图，48×48 是 1.5× 最近邻（像素画宁可硬边也不要糊）。

「关于」为什么不用 `MessageBoxW`：它的 `dwStyle` 只能挑系统预设的那几个图标，
要放自己的图标只能用 `MessageBoxIndirect`，并且 **`dwStyle` 必须带上 `MB_USERICON`**——
少了这一位，`lpszIcon` 会被忽略，弹窗上一个图标都不显示（踩过）。
另外 `lpszIcon` 传的是整数资源 ID，1 这种奇数地址过不了 `[*:0]const u16` 的对齐检查，
所以绑定里那个参数写成 `?*const anyopaque`，用 `w.resId(1)` 造。

`.rsrc` 的资源树必须是**三层**：根（按类型）→ 类型目录（按 ID）→ 语言目录 → 数据条目。
早先的版本只写了两层（类型 → ID → 数据条目），资源管理器能忍，但 `LoadIconW`/`LoadImageW`
会把下一层的目录头当成数据条目读、RVA 取到 0 直接失败——图标在标题栏和「关于」里都出不来。

```powershell
node tools\dump_icon.js 复扫雷.exe build\shots\rsrc   # 把 .rsrc 里的图标导成 PNG 核对
```

会把 GRPICONDIR 的每一档（尺寸/字节数/引用的 RT_ICON id）和导出的 PNG 列出来，
自检里也有一条断言（`testIconResourceOk`）确认 `LoadIconW` 与 16×16 的 `LoadImageW` 都拿得到。

## 素材：一张整图 + 一份槽位表（唯一来源）

`素材/` 里只有两样东西：

| 文件 | 说明 |
| --- | --- |
| `素材/图集.png` | 256×87 的整图，61 个槽位，**原生尺寸**（放大由程序按整数倍最近邻做，不再有 2×/4× 素材） |
| `素材/图集.json` | 槽位表：`version` / `width` / `height` / `slots[]`（`name` + `x,y,w,h`），**数组顺序就是槽位号** |

`tools/gen_atlas.js` 读这一对 → 校验（名字不重、矩形不越界、24 个显示值贴图齐不齐）→ 写出
`src/atlas.bin`（88 KB，原始 BGRA + 索引表），再由 `@embedFile` 编进 exe；运行时只从内存里的这份
数据建 DIB，**不读磁盘上的任何图片**。

> 早期版本是"61 张单张 PNG 按文件名映射再货架打包"（`数字2√5.png` → $D=k^2r$ 那套），
> **已作废**：那些散图挪到了 `素材/散图（已作废）/`，不参与构建也不再进版本库。
> 现在的等价性靠一条硬标准保证：**从整图重建出的 `atlas.bin` 与原来那份逐字节相同**
> （迁移时验过，SHA-256 一致）。

**改素材**：直接在 `素材/图集.png` 上改（槽位矩形不变就不用动 json；要挪/加槽位就用下面的
命令重新生成 `atlas.json`，再改名成 `素材/图集.json`）。

```powershell
node tools\dump_atlas.js src\atlas.bin build\素材导出   # 也可以直接传 复扫雷.exe
node tools\check_export.js                              # 验收：矩形表 / 整图像素 / 导出散图三项
node tools\diff_sprites.js build\素材导出_旧\sprites build\素材导出\sprites   # 这一轮改了哪几张
node tools\cmp_tiles.js num_8 num_18                    # 这几张「左旧右新」并排画一张图
```

`dump_atlas.js` 输出 `atlas.png`（1:1，保留 alpha，与图集逐字节一致）、`atlas.json`（槽位表）、
`sprites\`（逐张 61 个小图）+ `sprites.txt`，并把矩形表前 12 项打出来。
`tools\check_export.js` 是验收脚本，三件事：**图集的矩形表 == `素材/图集.json`**（防"改了素材没重建"）、
**图集的像素 == `素材/图集.png`**（防"图集是用旧大图建的"）、**导出的散图 == 图集对应矩形**（防导出写坏）。

### 素材更新流水线（改完 `素材/` 只跑这一条）

```powershell
powershell -ExecutionPolicy Bypass -File tools\update_assets.ps1
```

它按顺序做七件事，任一步失败就停下：

1. **素材指纹**：把 `素材\图集.png` + `图集.json` 的 SHA-256 记在 `build\素材指纹.txt`，和上次跑完时比对；
   一模一样就直接退出（不改版本号、不重建），要强制重跑加 `-Force`。
2. **存档旧导出**：`build\素材导出` → `build\素材导出_旧`（下一轮比对就用它当基线）。
3. **版本号 +1**：只改 `src\main.zig` 的 `APP_VERSION` 与 README 里那行（`-NoBump` 可跳过）。
4. **重建**：`build.ps1` 全流程（重打图集 → 编译 → 注入图标 → 规则自检 + 界面自检）。
5. **重新导出并验收**：`dump_atlas.js` + `check_export.js`（矩形表 / 整图像素 / 导出散图三项全对）。
6. **逐像素比对**：`diff_sprites.js` 列出改动的槽位，再用 `cmp_tiles.js` 把**只有这一轮变了的**
   那几张画成 `build\数字贴图对比.png`（左旧右新）；一个槽位都没变时会把上一轮留下的对比图删掉。
7. **对照表 + 抖动检查**：重画 `build\素材导出\对照表.png`，并把界面自检连跑 `-Flakes N` 次（默认 15）。

> 脚本本身必须保持 **UTF-8 BOM**，否则 PowerShell 5.1 会按 ANSI 解析、中文全变乱码——
> 编辑工具保存后会去掉 BOM，改完记得补（README 末尾的坑列表里有这条）。

**槽位名就是 Zig 里的常量名**：`num_8` 表示"显示值 $D=8$ 的那张图"，`flag_2` 是负实旗，
`led_i` 是虚雷计雷器第四格那个 $i$……它们写在 `素材/图集.json` 的 `slots[].name` 里，
由 `gen_atlas.js` 原样搬进 `src/assets.zig`（`pub const num_8: u16 = 20;` 这种）。
所以**改槽位名等于改代码**，要改就两处一起；`assets.zig` 是生成物，别手改。

`gen_atlas.js` 会挡住三种事故：**名字重复**、**矩形越界/尺寸非法**、**24 个显示值贴图不齐**
（$D \in \{0,1,2,4,\dots,64\}$ 那 24 个 `num_D` 一个都不能少），所以"换了图但没生效"不会静默发生。
核对映射最省事的办法是跑一次素材对照表：

```powershell
.\复扫雷.exe --shot build\shots\sheet.bmp --sheet --quiet
node tools\bmp2png.js build\shots\sheet.bmp build\shots\sheet.png
```

第一行就是 24 个显示值（按 $D$ 升序，下方标 `D=`），它是从**编进 exe 的那份图集**渲染的，
所以看到新图就等于新图真的进去了。

想自己验证：把 `复扫雷.exe` 单独复制到一个空目录（周围没有 `素材/`）再跑，界面照样完整：

```powershell
.\复扫雷.exe --shot-window shot.bmp --demo    # 贴图、人脸、LED 全在
.\复扫雷.exe --selftest r.txt                # 自检 31 条照样全过
```

也可以直接翻二进制：exe 里能找到图集魔数 `CSAT`（偏移约 46 KB 处），但**找不到 PNG 文件头**
（`89 50 4E 47`）——图集是解包后的原始像素，连原始 PNG 字节都不在 exe 里。

## 几个实现上的取舍

- **不加应用清单（manifest）**：因此 comctl32 走 v5，EDIT/BUTTON 是经典 Win95 立体外观，
  和棋盘贴图同一套审美；代价是文件图标要自己注入 `.rsrc`（见 `tools/set_icon.js`）。
- **进程声明 DPI 感知**，贴图只做 1×/2×/3× 整数倍最近邻放大，保证像素锐利；缩放可在菜单里切。
- **窗口尺寸固定**（不可拖拽改大小），和原版扫雷一致；换难度时按棋盘重算客户区大小。
- **没有底部状态行**：原版扫雷底部就是空的。判据不通过时**不作任何提示**（§6.3 要求只给文字反馈，
  这里连文字也去掉了），`Game.msg` 只留给自检断言用。
- **计雷器显示的是"这一类雷还剩几颗没标"，并且带上这一类雷自己的符号与单位**，
  于是一眼就能看出这四个数合起来是 $k_1 - k_2 + k_3 i - k_4 i$：

  | 面板 | 显示 | 格数 |
  | --- | --- | --- |
  | 正实雷 $+1$ | 四格数字，前导零补齐（$8 \to$ `0008`） | 4 |
  | 负实雷 $-1$ | 负号占一格 + 三格数字（$-9 \to$ `−009`） | 4 |
  | 正虚雷 $+i$ | 三格数字 + 一格 `i`（$9 \to$ `009i`） | 4 |
  | 负虚雷 $-i$ | 负号 + 两格数字 + 一格 `i`（$-8 \to$ `−08i`） | 4 |
  | 计时器 | 四格数字（$83$ 秒 $\to$ `0083`） | 4 |

  所以**标一颗负实旗帜会让那个负数朝零走**（$-9 \to -8$，看起来就是"数字增加"），
  标正实旗则让它减小；虚雷第四格是固定的 `i` 单位（素材 `计时i.png`，13×23）。
- **五块 LED 面板（四个计雷器 + 计时器）都是同样四格，而且每一格都有内容**：
  实雷与计时器是**四格数字**（第四格是真数字，不是空 LED），虚雷是三格数字 + 一格 `i`。
  所以五个框等宽，竖排那四行也一行不差；负数用一格当负号（于是数字少一位）。
  没开局时各类雷的颗数还没抽出来，五个面板都画空格子，**虚雷那格 `i` 也画 `计时空`**，不留白。
- **数值超出这个范围才加一格**：实雷与计时器超过四格数字（$\ge 10000$ 或 $\le -1000$）、
  虚雷数字部分超过三格（$\ge 1000$ 或 $\le -100$）时，那一块自己加宽一格；
  表头宽度按常态四格算，溢出的极端配比只让那一块变宽
  （自定义上限 40×30 = 1200 格，棋盘宽度远大于计雷器，压不到人脸）。
  计时器不会溢出：`timerSeconds()` 自己夹在 9999 秒。
- **四个计雷器竖排成一列**放在表头左侧：横排时四个三位计数器加起来比棋盘还宽，人脸只能被挤到右边；
  竖排之后表头宽度只剩一列的宽度，**人脸就能稳稳落在窗口正中**（原版的位置），计时在右侧垂直居中。
  代价是表头变高（4×26z + 行距 + 内边距 ≈ 120z），窗口相应变高——嫌大就把缩放切到 100%。
  计时器从三格改成四格之后，表头内容宽了 13z：**只有 9×9 这类窄棋盘会跟着变宽**
  （初级 200% 缩放：客户区 358 → 384 像素），中级/高级都由棋盘宽度决定，不受影响。
- **窗口标题固定**为 `复扫雷 Complexweeper`，不塞难度或局面信息（菜单里也不再标当前难度，
  想看当前是哪一档就点开「游戏」菜单，或看棋盘尺寸）。
  包名统一为 **`复扫雷`**：产物 `复扫雷.exe`（`build.ps1` 里的 `$final` 一处定）、标题、
  `关于复扫雷`、自检报告抬头、README 标题、ps1 工具里的引用全都用它；
  只有历史文档 `RULES.md`、网页原型 `demo/`、以及项目根早先网页版产物 `release\复数扫雷.exe`
  还叫「复数扫雷」。**构建脚本的"占用检查"按进程名里的「扫雷」匹配，不写死包名**，
  所以改过名的副本也能被认出来。
- **人脸按钮 = 那张 24×24 贴图本身**：素材里已经把立体边画进去了（上/左 2 像素白高光、下/右 2 像素
  `#808080` 阴影，按下那张是反过来的），所以**不能再自己画一圈边框**，否则会套出双层边——
  就是看起来"多了一层底图"的那一圈。
- **人脸贴图整体往左上微调**：贴图里的脸在 24×24 中偏右下半个像素（左边距 5、右边距 4，上下同理），
  再加上手动微调，靠 `src/main.zig` 里的 `FACE_NUDGE` 常量控制（单位是屏幕像素，改一行即可）。
- **五张人脸都在 `素材/` 里**：`脸普通`（开局）、`脸按下`（**只有按住人脸按钮本身**才是它，
  包括结束后按住人脸准备重开）、`脸扫雷`（在棋盘上按住任意键准备翻格/插旗/展开时，以及翻格/插旗/展开
  真正生效的那一瞬间闪一下，约 200ms，靠一次性定时器收回）、`脸死亡`（踩雷）、`脸胜利`（通关）。
  优先级是 按下脸 → 死亡/胜利 → 脸扫雷 → 普通脸（见 `faceSprite()`）。
  五张都有自检兜着：胜利/失败两张有专门断言；按棋盘时必须是 `脸扫雷` 而不是 `脸按下`
  （`!testFaceDown()` + `testFaceSpriteIsScan()`），只有按住人脸按钮时才切 `脸按下`（第 5 组那两条）。
  换素材时这五张只需要覆盖同名文件，构建会自动重新打包图集；素材对照表（`--sheet`）第五行会把五张脸全画出来。
  新素材在人脸上画了复平面的两根轴（实轴红/洋红、虚轴蓝/橙），四种颜色与棋盘里的旗帜、雷一一对应。
- **四种类型共用一套配色**（旗帜、雷、踩中底、标错叉的颜色都按这套走，换素材时照这个对齐就能一眼分类型）：

  | 类型 | 颜色 | RGB |
  | --- | --- | --- |
  | $+1$ | 红 | `255,0,0` |
  | $-1$ | 蓝 | `0,27,255` |
  | $+i$ | 紫 | `107,0,255` |
  | $-i$ | 天蓝 | `0,107,255` |

  雷和旗是同一色的"实心"与"旗帜"两种画法；`踩中X雷` = 同色雷 + 红底；`标错X雷` = 同色雷 + 红叉，
  并且**按玩家插错的那种类型取图**（不是按该格真实的雷型），所以看一眼就知道自己插的是哪种旗。
- **贴图宽高必须分开缩放**：素材里 LED 数字是 13×23（不是方的），格子/图标 16×16，人脸 24×24。
  `blitSprite(dc, sprite, x, y, dw, dh)` 收两个尺寸；方形贴图走 `blitSpriteSq` 简写。
  （踩过的坑：一开始只收一个 `size` 同时当宽高用，LED 数字被画成 13z×13z 的方块 —— 纵向被压掉 23/13，
  看起来像"纵向没放大"。）
- **LED 虚段可清理（默认关）**：素材里未点亮的段是用 `128,0,0` 与黑交替的点阵画的（半色调虚段），
  放大到 2×/3× 时每个点会变成方块。图集生成时可以把这些暗红像素抹成黑、只留点亮的段：
  把 `tools/gen_atlas.js` 里的 `CLEAN_LED_GHOST_SEGMENTS` 改成 `true` 重跑构建即可。
  默认 `false`，即**按素材原样渲染**。
- 图集里的贴图是不透明的，直接用 `SRCCOPY` 贴；棋盘格 16×16、计时数字 13×23、人脸 24×24，与原素材一致。

## 自检

```powershell
.\复扫雷.exe --selftest build\selftest.txt    # 规则层，31 条断言
.\复扫雷.exe --uitest   build\uitest.txt      # 界面层，197 条断言（投递消息，无需桌面）
```

规则自检覆盖：同种子同开局格必须生成同一棋盘；指定配比必须被精确执行（5 种配比 × 3 种子）；
纯实/纯虚局面所有显示值必须完全平方；**连片结果与测试里独立实现的洪水填充逐格一致**且从不翻到雷；
显示 `0` 的格子绝不连片；开局必为空白格并连片；判据与独立实现逐格一致；插旗不限量与循环顺序；
**旗子保护格子**（插旗格翻不开、旗帜与计数原样保留、连片展开也绕开它、撤旗后才能翻）；胜负判定；判据不过时展开不改变棋盘。

界面自检覆盖：**窗口标题**（`GetWindowTextW` 读回来与 `APP_TITLE` 比对，且只剩「复扫雷」）与
**图标资源**（`LoadIconW` / 16×16 的 `LoadImageW` 都拿得到）；
**左键按下只是预览**（记下按住的格子、画成空白格、不开局也不翻开，松开才翻）、
**拖动时预览跟着走 / 拖出棋盘取消**；三个难度菜单切对尺寸；缩放菜单生效；**菜单结构**（帮助下拉只剩「玩法与操作 / 分隔线 /
关于」，被删掉的「显示值对照表」ID 201 绝不能再出现，游戏下拉里有「最高分纪录」）；左键开局并连片；
右键循环插旗（**连点时第二下收到的是 DBLCLK，也要循环**）、**开局前插旗且活过开局**、中键不清旗、**插了旗的格子左键点不开（撤旗后才开）**；
**最高分纪录**（记账 / 更慢不覆盖 / 自定义不计入 / 弹窗正文只有三行）；
点人脸重开（含按下态与「按下」那张贴图确实被选中）；<kbd>F2</kbd> 重开；
**两条展开路径**（左右键同时 / 中键）：按住时邻域待展开的格子显示空白预览、松手才展开
（判据不过则不动棋盘、只给 `judge_fail` 枚举），并且**双击不再展开**；版式边界；
**自定义对话框**（预填、高度/宽度/合计三种越界校验、均分按钮、确定后按新配比重开并落到棋盘上）；
**整局通关**（用消息把非雷格全部点开 → 判定胜利 → 胜利脸）；**踩雷结算**（死亡脸 + 记录踩中格）；
两者都额外断言**结束后雷区不再响应**（按下不压格、不换脸，右键不改旗）；
**翻格/插旗/展开成功时脸闪「脸扫雷」**（`testFaceSpriteIsScan` + `testFaceFlashExpire`）；
按住手势与脸的对应：**按住棋盘（左/右/中任一）一律播「脸扫雷」**；「脸按下」只属于人脸按钮。

> 「判据通过时中键真的展开」这条是补出来的：只断言"中键没清旗"看不出它到底有没有换成展开，
> 所以自检里按真值把邻域插满旗（这一步会先验判据确实为真），再投一条中键消息，数翻开的格数。

> 这两套自检不是摆设：界面自检抓出过「均分按钮读错编辑框」（把宽度框当成第一种雷），
> 规则自检抓出过「`computeClues` 少判空邻居导致越界读、显示值算错」——后者在旧版本里
> 因为越界正好读到 0 而一直"看起来正常"。
>
> **自检自己也会坏，而且坏得很安静**：某一版界面自检每 6 次里有 1 次失败，原因是第 3b 组的
> 拖动测试随机挑到了雷格，把局面结束掉，后面第 4 组"插旗循环"的八条断言就成片地红——
> 看上去像插旗坏了，其实是测试自己把局面玩死了。修法有两条：拖动只挑非雷格，
> 并且在第 4 组开头加一条前置断言（`!over`），以后再出问题能直接指到正确的位置。
> 另一处偶发是第 7b 组挑到了"邻域里除了雷没有别的可翻格子"的数字格，
> `tryExpand` 会因为没格子可翻而静默返回。**改完连跑 40 次为 0 失败**——
> 偶发失败比稳定失败更费时间，发现一次就得连跑着抓出来。

`--dump 文件` 可以顺带把局面数字写出来（各类雷数、已插旗数、还差几颗），用来核对计雷器读数。

> **参数解析的坑（已修）**：`--sheet` / `--shot-window` 既可以跟在 `--shot 路径` 后面当开关用，
> 也可以自己带路径（`--sheet 路径`）。早先的实现一律"期待下一个参数是路径"，于是
> `--shot x.bmp --sheet --quiet` 里的 `--quiet` 被当成文件名吃掉，渲染结果存进了一个叫
> `--quiet` 的文件（目录里真出现过 `--shot` / `--quiet` / `--dump` 三个 1.4 MB 的怪文件）。
> 现在只有"还没拿到输出路径"时才会去期待下一个参数。

**按键行为要拿真鼠标验**：消息级自检能证明"收到 LBUTTONDOWN 时状态对不对"，但证明不了
"真实点击时系统到底发了哪些消息"——右键连点丢失就是栽在这里：第二下按下收到的是
`WM_RBUTTONDBLCLK` 而不是 `WM_RBUTTONDOWN`，消息级测试里手写 `RBUTTONDOWN` 永远发现不了。
`tools/click_probe.ps1` 用 `SendInput` 注入真实鼠标事件，逐步 `PrintWindow` 抓图：

```powershell
powershell -ExecutionPolicy Bypass -File tools\click_probe.ps1 -Script press -OutDir build\probe\press
# -Script: fresh 开局前右键 / start 开局后右键 / dbl 快速连点两下 / press 按住不放再松开
#          flagblock 插旗后左键点同一格（画面应与插旗后完全一致）
#          chord     左右键同时点击扫一圈，找"按住有预览、松手有展开"的格子
#          both      左+右同时按住再松开：那一格不该被翻开（走的是展开那条路）
#          faces     逐个手势抓脸：左/左右/中/右键按住=脸扫雷，按人脸=脸按下
```

`press` 会依次给出 `z_before` / `a_held` / `b_released` 三张图：按住那张里被按的格子应该是
**平的空白格**，松开那张才出现数字。注意比对时要裁到棋盘区域再比哈希：整窗哈希会被计时器
的秒数变化干扰，曾经因此误判过"连点没生效"。

**弹窗怎么抓**：`--shot` 只能拍自己的客户区，而玩法与操作 / 关于 / 最高分纪录都是模态 `MessageBoxW`，
进程内的抓图代码在它弹出来时根本轮不到执行。`tools/shoot_dialog.ps1` 从外面来：启动 exe → 给主窗口
`PostMessage(WM_COMMAND, 命令ID)` 把弹窗叫出来（`-DemoWin` 则不点菜单，等结算弹窗自己蹦出来）→
轮询该进程的 `#32770` 窗口 → `PrintWindow` 存 PNG。

> **三个 .ps1 必须带 UTF-8 BOM**（`build.ps1` / `shoot_dialog.ps1` / `click_probe.ps1`）：
> Windows PowerShell 5.1 对无 BOM 的文件按 ANSI 读，中文字符串会直接变成语法错误
> （报错长这样：`Unexpected token 'zig'`、`The string is missing the terminator`）。
> 坑在于**用编辑器/脚本改这几个文件很容易把 BOM 丢掉**，所以改完先确认一下：
>
> ```powershell
> $b = [System.IO.File]::ReadAllBytes('build.ps1')[0..2]
> ($b | ForEach-Object { $_.ToString('X2') }) -join ' '   # 要看到 EF BB BF
> ```

```powershell
powershell -ExecutionPolicy Bypass -File tools\shoot_dialog.ps1 -Command 200 -Out build\shots\help.png    # 玩法与操作
powershell -ExecutionPolicy Bypass -File tools\shoot_dialog.ps1 -Command 202 -Out build\shots\about.png   # 关于
powershell -ExecutionPolicy Bypass -File tools\shoot_dialog.ps1 -Command 106 -Out build\shots\best.png    # 最高分纪录
powershell -ExecutionPolicy Bypass -File tools\shoot_dialog.ps1 -Command 104 -Out build\shots\custom.png  # 自定义雷区（自绘窗口类）
powershell -ExecutionPolicy Bypass -File tools\shoot_dialog.ps1 -DemoWin     -Out build\shots\newrec.png  # 破纪录时的「新纪录！」
```

脚本还会把弹窗里每个 Static 控件的文字打出来，所以文案（换行、空格、占位符）不用看图也能逐字核对。
「自定义雷区」是我们自己的窗口类，脚本会同时认 `#32770` 和 `ComplexSweeperDlg` 两种对话框。

> **从外面驱动对话框有两个坑**（都踩过）：
> 1. **抓到的可能是旧画面**：窗口在后台时 DWM 没给它合成新表面，改完控件内容立刻 `PrintWindow`
>    会拿到改动前的样子。脚本现在抓之前先 `SetForegroundWindow` + `RedrawWindow(ALLCHILDREN|UPDATENOW)`
>    （`-NoRefresh` 可关掉对比验证）。
> 2. **跨进程给 EDIT 写文本，程序自己读不到**：`SetDlgItemText` 从另一个进程写进去，
>    外面 `GetWindowText` 能读回新值，但**程序内部读到的仍是旧值**——所以"注入 99 触发校验失败"
>    这种玩法不可行（表现为对话框正常提交关闭，白折腾一场）。校验/提示这类**行为**要用
>    `--uitest` 的进程内钩子验（`testSetEdit` + `testApplyDialog` + `testDialogTexts`），
>    截图只用来核对**外观**。

`-DemoWin` 走的是 `--demo-win --shot …`（不加 `--quiet`）那条路：造一个已通关的局面 → 真实结算 → 弹窗。
它会**真的往注册表写一条纪录**（这个是故意的，正好验证落盘），拍完执行
`reg delete HKCU\Software\Complexweeper /f` 清掉即可。
想让「最高分纪录」三行都显示成有数值的样子，也可以先临时写三个 DWORD 再拍。

## 与 demo 的关系

`demo/complex-minesweeper.html` 是网页原型，用来试规则、跑平衡性分析；正式版是它的原生重写，
规则完全对齐（同一套 mulberry32 种子 PRNG，同种子 + 同开局格会生成同一个棋盘）。

**界面与规则的差异**：操作与文案以正式版为准。demo 还留着旧的一套——中键清旗（正式版改成中键展开）、
侧栏那张显示值对照表（正式版的帮助菜单里已经删掉）、**左键点已插旗的格子会清旗并翻开**
（正式版改成"旗子保护格子，点不开"，`RULES.md` §5.5 已同步）。demo 是原型，没跟着改。
